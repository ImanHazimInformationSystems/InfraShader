# Grass spray over the selected site — 13 November 2026

Affected IDs: L04 and L06. User requested a Sims-style spray with exactly six grass textures to colour the selected Layout site. Existing implementation, modified/untracked work and proposal/quantity safeguards were preserved. No external imagery, package, migration, new endpoint, paid resource, deployment or Excel export.

## Behaviour and architecture

- Layout > Ground has six original procedural looks: Fresh lawn, Meadow, Fine turf, Dry grass, Deep green and Wild grass. Choose a look, set radius (1–100 m), click or drag to paint. Cursor shows approximate brush extent. Eraser removes paint; Clear removes the scenario's strokes; existing Layout undo/redo reverses each completed stroke/clear. Escape cancels the current stroke. A Stamp at map centre button provides a keyboard-operable dab using the same validated action (the button itself was type/lint checked, not separately browser exercised). The live raster preview is replaced with the validated result, or rolled back on error.
- `GroundPaint.tsx`, `ground-paint.css`, `services/ground-paint.ts`: clipped 1024×1024 canvas image over the selected geographic site. Original grass tiles include varied blade/clump colour and mowing-style patterns. Raster is clipped to the exact current outline and georeferenced by public Mapbox Mercator coordinates; it sits below project roads/plants. Standard uses its middle slot; the neutral test style uses the ordinary project layer order. Canvas updates stop after texture upload rather than running a permanent animation loop. The surface is presentation only and has finite raster resolution, not surveyed material coverage.
- `ground_paint.py`, `workspace.py`, `spatial_editor.py`, `main.py`: strict bounded stroke definitions (six grass IDs or eraser, positive bounded radius, up to 64 finite WGS84 points; 128 strokes per scenario). The existing authorised spatial-edit endpoint validates new strokes near the selected site, rejects foreign/distant/unsupported positions and stale revisions, and appends/clears visual data. Stored strokes remain admissible within project extent after boundary edits; the renderer clips them to the current boundary. Save/restore uses existing JSON revisions; no database migration. Paint creates no work items, quantities, rates, plant records, terrain heights or analytical shade inputs.
- `TownLayout.tsx`, `studio-context.ts`, `StudioShell.tsx`, `GeometryWorkspace.tsx`, frontend workspace schemas: Ground joins the existing tool tray; in-progress paint guards scenario/tool changes and saving until committed/cancelled. Only the visible Layout tool captures painting/planting input; hidden panels cannot continue stamping. Completed paint participates in existing save, recovery, expected-revision, history and undo/redo flows. Baseline and each option retain independent paint. Demo retains its existing separate workflow.
