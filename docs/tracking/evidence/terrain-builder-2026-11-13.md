## Implemented behavior

- `TerrainBuilder.tsx` / `terrain-builder.css`: responsive maroon/silver brush cards, circle/square shapes, metre size, speed, height/depth offset, soft edges, navigation, keyboard site-centre dab, undo/redo/reset, pond removal, source/datum and explicit flat-start confirmation. Existing numeric/grid/contour tools remain under Precision terrain controls.
- `ObjectScene.tsx` / `domain/terrain.ts`: timed pointer-held strokes update the concept mesh until release or target; one release is one validated draft/history action. Escape/pointer cancellation reverts the whole gesture. Leaving the active terrain tool disables its brush. Map navigation is restored after sculpting. Raise/dig never cross the selected offset in their direction; erase approaches the declared original surface. User speed is a graphical brush setting, not machine productivity.
- `services/terrain-mesh.ts`: Three.js ground subdivides the actual projected boundary, samples the existing heightfield, and includes round/square horizontal concept water surfaces. Topology is bounded to an approximate 16,000-triangle budget; complex outlines can render more coarsely. The 33×33 grid remains the stored concept source; this is a model over the site, not edited provider elevation or a survey surface. Provider elevation remains subject to the existing concept-terrain gate.
- `terrain.py`: additive circle/square pond footprint metadata (old records default square); water requires bed nodes below level and a footprint inside the site. Ponds do not flow/fill automatically. Existing metre frame, height limits, eight-pond bound and stale save/access checks remain.
- `workspace.py`: explicit manual site-work records are ordinary proposed manual items with resource/activity, tools, assumptions, supplied quantity and h/m³/item unit. The backend derives their active quantity from the supplied record and builds the human-readable source note. No cut/fill or water volume is derived. Records carry a backend terrain signature; edits to the terrain or ponds mark previous records stale until reviewed for the current terrain.
- `domain/pricing.py`, `calculations.py`, `schedules.py`: existing Decimal, sourced rates, saved schedule and estimate pipeline. Terrain without any recorded site work produces a visible missing-scope line. Stale work is excluded from priced subtotal and cannot claim estimate completeness. Resource inclusions prevent duplicate global charges. Existing parent quantity, rate basis/unit/currency checks, access, revisions and retained snapshots remain authoritative.

Supplied work quantities/rates and explicit exclusions require user review; listed work does not prove complete construction scope. Reset keeps old work records visible and stale until removed/reviewed. Baseline is existing context; proposed work belongs to options.

Local fixture browser checks use synthetic data/offline map style; they do not qualify live Mapbox ground/building depth interactions, real elevation, physical devices, assistive technology, production deployment or customer acceptance. No remote writes, paid resources, dependency additions, migration or Excel export. Broad unrelated suites and live-provider/field/customer gates are not rerun for this slice.
