## Scope and implementation evidence

- `apps/api/app/terrain.py`: bounded heightfield/pond schema, frame validation, edited-terrain detection and bilinear ground-contact interpolation.
- `apps/api/app/workspace.py`: scenario-specific private terrain in existing revisioned workspace JSON; backend-calculated object anchors; history restoration strips derived anchors and recalculates them. No migration required.
- `apps/api/app/main.py`: authorised project terrain-frame endpoint, derived from validated boundary and metric CRS.
- `apps/api/app/domain/shade.py`: rejects comparisons when any scenario has edited terrain or a concept pond.
- `apps/web/src/domain/terrain.ts`: deterministic bounded brush drafts, metric slopes, bilinear contacts and interpolated triangle contours capped at 20 levels.
- `apps/web/src/components/TerrainPanel.tsx`: explicit flat start/datum/source; per-scenario raise/lower/smooth/flatten, metric brush controls, numeric region/elevations, before view, reset, rectangular ponds/water/depth and isometric diagram.
- `GeometryWorkspace.tsx`, `DrawingMap.tsx`, `domain/workspace.ts`: existing workspace undo/redo/revisions, request sanitisation, stale-shadow suppression and disabled flat-ground 3D buildings when terrain is edited.

See [user guide and precise limitations](../../terrain-concepts.md). The synchronized local-frame SVG view is a concept diagram, not a Three.js/MapLibre terrain renderer. Rectangular pond regions, representative-point object contacts and explicit flat-start inputs are the supported forms. No imported DEM, cut/fill, pond volume, hydrology, terrain shade or engineering certification is claimed.
