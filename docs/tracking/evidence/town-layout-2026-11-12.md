# Town-builder Layout — 12 November 2026

Affected IDs: L04, L09 and L31. The user requested a simpler town-builder interaction with editable roads, dirt/pavement/stone looks, simple map plants and automatically estimated selected-site area. Existing local work was preserved. No dependency, migration, new endpoint, deployment, external write or Excel export.

## Implemented

- `TownLayout.tsx` / `town-layout.css`: Select, Roads and Planting tool tray; estimated area card (m²/ha), draft item count, undo/redo, item selection/removal and links to specifications/cost. Real Studio starts in proposed Option A. `StudioShell.tsx` exposes precision tools separately; existing detailed workspace and Demo/Review workflows remain available. Generic forms, recovery prose and unused drawing controls are hidden in the simple immersive Layout, not removed from the architecture.
- `RoadEditor.tsx`: surface tiles, straight/bends/curved/free-shape buttons, visible editable concept width (4 m initial drawing preset), slider, drag/click/point editing and explicit Place/Cancel. Measurement notes default visibly to an estimated, unsurveyed concept trace; source and numeric controls remain expandable. Drawing presets are not construction standards. Existing authorisation, footprint/overlap validation, revisioned saves, layers/rates, estimate and BOQ paths remain authoritative.
- `roadwork.py`, frontend workspace schema: persisted optional surface identifier with pavement compatibility default for prior road records. `layout-textures.ts` creates original procedural dirt/pavement/stone/gravel patterns and plant symbols; `DrawingMap.tsx` applies them to project overlays and previews. Texture selection never sets a construction recipe, layer thickness or price. Preview clearing works while project sources are loading, so confirmed roads do not keep the temporary dashed preview.
- `workspace.py` / `spatial_editor.py` / `main.py`: estimated projected selected-site area is returned even before workspace creation; validated boundary area is derived again on validation/save/read. Round-tripped area metadata is discarded and recalculated, including restore. Unsupported large/cross-zone boundaries return area unavailable. The existing grant-checked spatial-edit endpoint admits proposed concept tree/shrub/flower point markers and rejects invalid/out-of-bound/Baseline placement. Metadata persists in existing JSON workspace revisions; no new persistence service.
- Planting clicks create explicit unpriced concept markers (one display tree or cluster per marker). Species, nursery size, installation scope, physical crown dimensions and rates are not inferred. Existing plant-specification/schedule workflow can be opened deliberately. Map symbols remain excluded from tree analytical shade. Selection, removal and undo are connected; precision editing remains available for more detailed geometry work.
