## Implementation coverage

- `apps/api/app/site_constraints.py`: bounded typed records, source/uncertainty, consent, inspection date, geometry, design/photo links, responsibility/due date, critical flag, response, verification record and resolution. Map/traced/estimated sources cannot claim verification. Records are user declarations, not externally authenticated survey results.
- `apps/api/app/workspace.py`: validates geometry/links, checks active project-owned photo links on save, preserves the register in existing revision history and applies existing project grants/archive/conflict controls. Constraint records never enter quantity calculations.
- `apps/api/app/evidence.py`: retains the existing private upload/proxy/EXIF sanitisation; prevents archiving a photo while a current saved constraint links to it. Earlier workspace source values remain in immutable revisions.
- `apps/web/src/components/SiteConstraints.tsx`: private register, consented numeric/map capture, search, critical/due-sorted site-check queue, assignment/resolution form, photo/design links and retained invalid drafts. Responsive cards replaced the cramped table after visual inspection.
- `GeometryWorkspace.tsx` / `DrawingMap.tsx`: view-only constraint layer; applied register edits participate in undo/save/history; pending constraint forms block calculation/issue and restore. `CalculationsPanel.tsx` displays unknown/critical counts before use.
- `calculations.py`, `domain/calculations.ts`, `IssuedPdf.tsx`: frozen, allowlisted count/limitation summary. No automatic publication of private titles, source text, geotags, responsible people or verification references. Explicit photo issuance remains independent.
