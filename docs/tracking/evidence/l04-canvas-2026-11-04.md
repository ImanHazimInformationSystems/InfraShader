## Scope and implementation

The existing bounded CORE/NEXT toolkit was inspected before editing: metric moves/rotation/dimensions, snapping, multi-selection, groups/layers/locks, arrays, saved browser selections, split/merge/cutouts and transactional draft undo already existed. This checkpoint connects that toolkit to a primary canvas rather than rebuilding it.

- `GeometryWorkspace.tsx`: primary canvas switches between the existing 2D map and 3D design scene. Work-item selection is shared with the inspector/list and scenario. Inspector coordinates follow validated draft edits/undo; deleted selection is cleared. Existing save/revision/history and dirty-draft controls remain authoritative.
- `ObjectPalette.tsx`: renders the scenario scene into the primary canvas using a React portal; the nominal asset preview remains in the library. Existing terrain/object edits still use validated backend previews. General geometry is requested with cancellation and hidden while stale/unavailable rather than rendering an obsolete draft.
- `ObjectScene.tsx`: existing Three.js terrain and admitted presets now include ordinary polygon/line/count work geometry. Polygons retain interior rings; sourced building/canopy heights extrude and unknown heights remain flat. Generic point markers are explicitly work geometry, not licensed asset meshes. General polygons use representative-point terrain contact and lines use vertex samples, not a terrain-conforming engineering surface. Scene selection uses stable IDs. View is retained across view switching; fit/retry reconstructs the renderer after context loss.
- `spatial_editor.py` and `main.py`: read-only `/spatial-scene` endpoint checks project access, validates the supplied workspace and projects ordinary geometry into the same UTM frame as quantities using existing PyProj/Shapely. It neither persists nor advances revisions; normal writes retain existing grants and stale-revision guards.
- `tests/reference-browser/objects.spec.mjs` and `editor.spec.mjs`: updated scene-location locators to follow the actual UI relocation. Existing object capacity and terrain stroke assertions remain.
