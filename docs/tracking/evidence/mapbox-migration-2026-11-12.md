## Provider observations and unresolved live gate

Authorized direct style requests: Standard and Standard Satellite both HTTP 200, style version 8. The actual Standard schema exposes `show3dObjects`, `show3dBuildings`, `show3dTrees`, `show3dLandmarks` and `show3dFacades`; the returned Standard Satellite schema did not expose those 3D toggles. Therefore the application retains Standard's 3D import and inserts Mapbox Satellite raster in the `middle` slot. Public style ordering showed that slot precedes the tree/building models; the earlier bottom-slot experiment was covered by native polygons and was corrected. This is one renderer/view composition, not parallel editable project stores.

Real Standard content rendered in the sampled KLCC/Kuala Lumpur viewport, including provider buildings, tree scenery where supplied and contextual shadows. Coverage is not asserted globally. `artifacts/mapbox-provider-coverage.json` records sanitized 404 paths for absent `mapbox.procedural-buildings-v1` tiles; native coverage gaps remain visible/disclosed. Those are not surveyed completeness claims.

**Real satellite image tiles remain blocked:** browser requests and independent documented Raster Tiles API requests return HTTP 429, body `{"message":"Too Many Requests"}`. TileJSON metadata succeeds (HTTP 200). Comparison against a streets-raster endpoint also returned 429. Safe observed headers include `X-Rate-Limit-Limit: -1`, interval 60 and `X-Cache: Error from cloudfront`, without Retry-After. The official default raster rate limit is much higher than this test volume, but Mapbox's public documentation does not define a `-1` limit. No particular cause (spent allowance, billing, account restriction or transient provider behavior) is claimed.

The user reported no displayed usage. [Mapbox statistics guidance](https://docs.mapbox.com/accounts/faq/what-statistics-are-available-for-my-mapbox-account/) states that usage can take up to 24 hours to appear and statistics do not display API rate-limit/performance/status information. The UI therefore reports rate limiting rather than claiming exhausted monthly usage. The supplied token was separately validated successfully; no secret or account management operation was attempted. The user was informed during work. Live imagery must be rechecked when the provider returns successful tile responses.

To complete local software verification without hammering the blocked endpoint, `tests/mapbox-browser/context.spec.mjs` explicitly intercepts satellite tile responses with `tests/fixtures/mapbox-satellite-test.png` (a synthetic checkerboard). These tests exercise the actual Mapbox raster decoder/layer slots alongside live Standard data. Screenshots have a visible **Synthetic imagery fixture · integration test only** label. This is integration evidence only, not proof that real satellite data works. No unapproved alternate imagery source or disguised fake satellite map is used in the application.
