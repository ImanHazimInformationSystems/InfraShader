The intended requirements come from the supplied catalogue, particularly controlling section 00, per-entry Scope decision and section 10. Repository inspection establishes present implementation, not whether a requirement is correct. Conflicts are recorded in [reconciliation](tracking/reconciliation.md).

Each [feature specification](features/) preserves its complete source block, intended user/purpose, priority, prerequisites, inputs, behaviour, outputs, access boundary, validation, history, criteria, exclusions, implementation evidence and remaining work. Canonical fields live in `tracking/feature-specifications.csv`; implementation facts live in `tracking/feature-register.csv`. Unspecified details remain explicitly unresolved rather than invented.

Section 00's focused pilot boundaries narrow broad activity lists. A CORE/NEXT label describes different slices, not a promise that the entire module belongs in the next increment. Legacy Delivery labels do not override the refined scope. D0/D1A/D1B/D2/D3/D4 are stages; zero-padded D01–D10 are application feature IDs.

Cross-cutting requirements in catalogue sections 00.6, 00.11–00.12, 07, 08 and 10 apply alongside feature contracts. They are preserved in the source snapshot and GLOBAL acceptance rows. The role matrix and example scoring weights are intended workflow policy, not proof of current role implementation or adopted procurement rules. Confirm rubrics, ties, missing-data handling and self-approval rules before implementing them.

Source coverage is recorded in `tracking/source-coverage.csv`. Every original feature ID is represented; The original PDF defined 84 S/L/O/A entries; user addendum L31 brings the current project roadmap to 85. K01–K06 refine parent workflows. F/D/E cross-reference them. R/N/X/I resources and P/EVD problem/evidence identifiers are context, not additional modules. LS/OR UI inventories describe views, not a second backlog.

Scope exclusions remain explicit: simulated weather is not observed weather or drainage evidence; bounded ground-shadow previews are not full Shadowmap coverage or field-validated comfort analysis. Tree/terrain/roof-facade coverage is not inferred. F18/L06 does not promise cut/fill, hydrology or pond volume. Report mockups are visual concepts, not running application evidence. AI is deferred; deterministic pricing or templates do not establish model-assisted features.

Stable `TRK-…` acceptance IDs are newly assigned and marked **derived — review needed**. Some descriptive requirements still need decomposition into exact fixtures and independent assertions; do not accept a compound row without reviewing it. The 160 original SRS identifiers are preserved as names, with full wording/threshold review explicitly outstanding. This documentation makes those gaps visible; it does not manufacture customer acceptance.
