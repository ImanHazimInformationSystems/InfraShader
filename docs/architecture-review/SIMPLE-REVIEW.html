INFRASHADER / PLAIN-LANGUAGE ARCHITECTURE

How InfraShader works

InfraShader has three main parts: the screen you use, the processing behind it, and the storage that keeps your work. These parts work together on your PC during local development.

1. The screen you use

Explore the map, choose a date and time, edit a site, compare options and view reports.

Runs in your web browser.

Your requests ↓ ↑ Results to display

2. The processing behind the screen

Checks what you are allowed to access, calculates shade previews and costs, and manages project changes.

Runs in the InfraShader application service.

Save changes ↓ ↑ Load saved work

3. The place your work is saved

Keeps project details, team permissions, prices, saved report data and private project photos.

Uses a database and private file storage.

This is called a three-tier architecture. A tier means a main part of the system; it does not mean you need three computers.

Services that help it work

  • Sign-in service: checks your account. InfraShader then checks which projects and actions you can access.
  • Map services: supply the map, available building information and location search over the internet.

During development, sign-in and private file storage run locally through Supabase.

Example: exploring shadows

  1. You choose a place, date and time.
  2. The browser reads available buildings from the map.
  3. InfraShader calculates a shadow preview.
  4. The browser draws the result on the map.

Missing buildings or uncertain heights can limit the preview. Exploring does not automatically save a project.

Example: saving and reporting

  1. You edit and save a project.
  2. InfraShader checks your access and the information.
  3. The database keeps the saved changes.
  4. When you issue a report, InfraShader saves a fixed record of the allowed report data. Your browser turns that data into a PDF.

The PDF file itself is not currently kept in a server-side PDF archive.

What runs where?

On your PC: the website, application service, project database, sign-in service and private file storage.

On the internet: public map and location-search providers.

This describes the local development setup. It does not mean InfraShader has been deployed online or works fully offline.

Why did the detailed version show five layers?

The middle part has three jobs: receive requests, apply the rules and calculations, and connect to storage and other services. Counting those separately, plus the screen and storage, gives five layers. They still belong to the same three main parts shown above.

What this diagram does not mean

It describes how the current software is organised; it is not a claim that every planned feature is finished. Cross-organisation submissions, formal approvals, live weather data and an archive of generated PDF files remain future additions. Shade accuracy still needs real-world validation. The animated weather display does not change the calculated shade or prices.
