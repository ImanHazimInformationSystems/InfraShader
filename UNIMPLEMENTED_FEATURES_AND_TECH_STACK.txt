PURPOSE AND STATUS
This inventory distinguishes missing implementation from unfinished acceptance.
It includes the three previously requested explorer changes, which now exist.
It does not claim that the whole MVP is complete or field validated.
No packages, services, deployments or paid resources were added for this report.

PARTIAL = useful implementation exists, but stated work remains.
MISSING = the stated workflow is absent.
ACCEPTANCE = software exists; testing, policy or external evidence remains.
GATED = separate expansion requiring its prerequisites before implementation.
Candidate tools below are suggestions, not installed or mandatory dependencies.
Most remaining core work needs application development on the existing stack,
not replacement frameworks. Software and map-data licensing are separate matters.

======================================================================
1. YOUR THREE PREVIOUSLY REQUESTED MAP CHANGES
======================================================================

1.1 Automatic shadows from available map buildings - no manual modelling
Status: IMPLEMENTED as a bounded explorer preview; broader coverage unfinished.
The explorer reads available provider building footprints and heights and asks
the API to calculate ground shadows. Manual project modelling is not required.
Existing stack: MapLibre, OpenFreeMap building tiles, React/TypeScript,
FastAPI, pvlib solar position, PyProj projection and Shapely geometry.
Limits: loaded provider geometry, available heights, zoom 14 or closer, at most
500 building parts / 10,000 vertices / 128 vertices per ring per request.
Incomplete/unsupported geometry is omitted and preview limitations are shown.
This does not provide complete city coverage, terrain/tree shadows, or full
roof/facade occlusion. It does not create authoritative saved project geometry.
Remaining work for broader coverage is listed in section 3.

1.2 Date/time slider and sun direction/elevation
Status: IMPLEMENTED.
Date selection, time slider and UTC offset control update the preview. Sun
azimuth (clockwise from north) and elevation are displayed. Night and unsupported
low-sun conditions are reported.
Existing stack: React controls, FastAPI and pvlib; no new engine required.
Remaining enhancement: automatic location/date-aware timezone and daylight-saving
handling. Current offset is manual, with +8 appropriate for Malaysia.
Candidate: timezonefinder plus Python zoneinfo/timezone data; retain a clear
manual override and test ambiguous/nonexistent local times.

1.3 Fullscreen map with collapsible search and coordinate controls
Status: IMPLEMENTED.
Explore fills the browser window. Site search/coordinates can be hidden and
shown, and site controls collapse during map extent selection.
Existing stack: React, CSS and MapLibre; Photon search.
This means browser-window fullscreen, not an operating-system fullscreen mode.
No missing core implementation identified for this request. Broader physical
touch and accessibility acceptance remains part of section 2.

3. ADDITIONAL WORK FOR A MORE COMPLETE SHADOWMAP-LIKE EXPLORER
======================================================================
These are limits/enhancements beyond the implemented bounded preview. They are
not all previously agreed mandatory core requirements or promises of parity.

3.1 Reliable building coverage beyond currently loaded tiles - MISSING
Need: coverage accounting, robust tile-edge geometry handling, cached/spatially
queried building data, provenance and honest missing-height states.
Use: existing PostGIS, FastAPI, MapLibre, Shapely and PyProj.
Optional ingestion tooling: GDAL; GeoPandas/OSMnx only if selected data needs it.
Prerequisite: licensed footprints and suitable heights. Software cannot supply
accurate building heights where the source has none.

3.2 Courtyards, complex footprints and seam-safe building assembly - INCOMPLETE
Need: explicit holes/multipart semantics, duplicate/tile-clipping reconciliation,
resource bounds and regression fixtures before expanding preview coverage.
Use: Shapely/PyProj/PostGIS and a revised API/MapLibre extraction contract.
No new 3D framework is inherently needed for improved ground projections.

3.3 Roof/facade and full 3D occlusion - MISSING
Need: suitable 3D geometry and a tested ray/occlusion or shadow-map pipeline.
Candidate: Three.js for meshes/rendering/rays, with pvlib sun position and the
existing API/data stack. A visual GPU shadow alone is not validated numerical
shade analysis. Accurate meshes, resource limits and validation are prerequisites.

3.4 Terrain-aware shadows - MISSING / related to gated F18
Need: licensed elevation data, aligned horizontal/vertical units and datum, and
terrain occlusion calculations. Displaying terrain does not calculate its shade.
Candidate: GDAL, PyProj/PostGIS, MapLibre terrain or Three.js display, plus an
explicitly selected and tested terrain shadow calculation method.

3.5 Tree/vegetation shade - MISSING
Exists: tree objects and optional crown metadata; they are excluded from shade.
Need: crown geometry, height/source, opacity/season assumptions and validation.
Use/candidate: existing geometry/solar stack for an explicitly limited model;
Three.js only if a mesh-based approach is selected. A tree icon is insufficient.

3.6 Automatic timezone/DST - MISSING enhancement
See 1.2: coordinate-to-timezone lookup plus date-aware conversion and tests.

3.7 Provider resilience at wider usage - INCOMPLETE operational acceptance
Need: provider capacity assessment, cache/failure handling and approved hosting
or service arrangements. Public OpenFreeMap/Photon use is not a capacity guarantee.
Use: existing MapLibre/Photon adapters; assess self-hosting only when justified.
Open-source software does not imply unlimited free data or infrastructure.

F19 3D preset asset library [G11]
Need: licensed assets, dimensions/units, metadata, placement and performance caps.
Candidates: Three.js/glTF assets, existing private Storage and PostgreSQL metadata.
Blender is an optional asset-authoring tool, not required for every installation.

F20 GLB import [G11]
Need: rights confirmation, validated files, texture/resource caps, units/orientation,
safe upload/processing and device performance acceptance.
Candidates: Three.js GLTFLoader, existing upload/storage/API stack and a reviewed
glTF validation pipeline. Merely adding a loader does not complete secure import.
