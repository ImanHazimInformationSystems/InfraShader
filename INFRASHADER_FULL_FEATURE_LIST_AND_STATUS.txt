1. SCOPE, STATUS LABELS AND PRODUCT WORKFLOWS
=======================================================================
This updated catalogue consolidates the original feature guide, SRS v0.3,
stack specification v0.5, later user requests and repository evidence.
It replaces the older feature guide as a readable consolidated inventory;
it does not silently change the SRS or approve gated scope or release claims.
There is no F00 in the source feature numbering: product features are F01-F20.
F13 and F16-F20 are separate conditional/staged expansions.

BUILT: implemented within the stated scope, with recorded software checks.
BUILT / ACCEPTANCE OPEN: software exists, but external evidence remains.
PARTIAL: implementation exists; named software or verification work remains.
NOT BUILT / GATED: no working implementation; prerequisites remain.
PROPOSED ENHANCEMENT: a possible extension, not a silently added core promise.
Passing software tests does not establish site accuracy or release readiness.

Two audiences share the ground-site workspace:
- Developer project/landscape teams: compare options and issue a decision brief.
- Outdoor design-and-build contractors: scope work, estimate, price and issue
  a preliminary client proposal.
Both new developments and existing-site improvements are in the product scope.
Purpose changes questions/defaults/output; it never grants access permissions.

Ground-site workflow:
Sign in -> Explore Map or open project -> choose site -> brief/evidence ->
boundary/targets/items -> Baseline plus A/B -> shade/quantities/estimate ->
review -> developer brief OR contractor proposal -> PDF download.
Exploration may precede project creation; Browser Demo is a separate draft mode.

Planned building-surface workflow:
Choose building-surface mode -> define/import approved surface -> place work ->
quantities/options/estimate -> appropriate review/export. NOT BUILT.

Resources below use R01-R18, resolved to official links in section 7.
Most remaining core work reuses installed libraries. Optional tools are labelled.

Scope: project purpose, customer/internal sponsor, site/name/location, project

Edit/save the brief, show required fields/readiness and preserve revisions.

Technology: React/TypeScript forms, Zod, FastAPI/Pydantic, PostgreSQL/SQLAlchemy;

Current: BUILT / PARTIAL LIFECYCLE. Validated uploads, metadata, preview/download,

Technology: React gallery, FastAPI, Pillow image validation/re-encoding and

4. LATER USER REQUESTS AND CHANGES TO EXPLORE MAP
=======================================================================
These extend F03 and the F06-adjacent exploration experience. They do not replace
the saved project analysis requirements or remove provenance/accuracy boundaries.

E01 - Automatic shadows from available map buildings [BUILT, LIMITED PREVIEW]
User intent: choose/explore a site and see shadows without manually modelling
buildings, inspired by Shadowmap-style interaction.
Implementation: read loaded provider footprints/heights; prioritise nearby parts;
send bounded inputs to stateless POST /api/v1/explore/shadows; local sun/geometry
calculation returns a ground overlay. No project save or manual building needed.
Stack: MapLibre/OpenFreeMap + FastAPI/pvlib/PyProj/Shapely. R04, R06.
Limits: zoom >=14; up to 500 parts, 10,000 total vertices, 128 vertices/ring and
1,000 m provider height. Invalid/unsupported parts are omitted and counted.
Loaded tile boundaries/height defaults can leave gaps; preview is approximate.

E02 - Date/time slider and sun direction/elevation [BUILT]
Date, time slider and explicit UTC offset drive recalculation; sun azimuth and
elevation displayed. Default +8 suits Malaysia; elsewhere set site/date offset.
Night and sun below supported elevation report unavailable daylight shadows.
Automatic timezone/DST lookup is a PROPOSED ENHANCEMENT, not built.
Stack: React controls + pvlib API; optional timezonefinder/zoneinfo. R01, R06, R18.

E03 - Fullscreen exploration and collapsible controls [BUILT]
Browser-window map; hide/show search, site-name and coordinate controls; Projects
exit; controls collapse during two-corner site selection. Retain clear map view.
This is viewport fullscreen, not a claim of native operating-system fullscreen.
Stack: React/CSS/MapLibre. R01, R04.

E04 - Provider 3D and useful search failure recovery [BUILT]
Provider-height 3D is navigation/preview context. Keep 2D fallback and labels.
Explicit-submit Photon search preserves query on timeout, offers retry/cancel,
ignores late obsolete responses and retains map/coordinate alternatives.
Phone-sized live-provider workflow passed after the search recovery changes.
Stack: MapLibre, Photon, React request cancellation/state. R01, R04.

E05 - Full Shadowmap-like coverage [NOT ACHIEVED; EXTENSIONS NEED SCOPE]
Still absent/incomplete: coverage beyond loaded tiles; robust courtyard/complex
multipart/seam assembly; roof/facade occlusion; terrain/tree shade; automatic
timezone/DST; production-scale provider capacity/resilience.
Possible resources: PostGIS/cache/ingestion and Shapely for building data;
GDAL/GeoPandas/OSMnx where justified; Three.js and a validated occlusion pipeline
for richer 3D; terrain sources and a separate terrain engine; tree assumptions
and validation; timezonefinder for timezone lookup. R03, R06, R11, R13, R18.
No library supplies missing accurate heights or validates field performance by
itself. A Three.js visual shadow is not authoritative numerical shade coverage.

E06 - Sun, sky and day/night simulation [BUILT; DEVICE ACCEPTANCE OPEN]
One date/local-time/explicit-offset clock, 24-hour minute timeline, play/pause,
labelled speed, offset-aware Now and approximate sunrise/noon/sunset shortcuts.
Bounded pvlib daily samples use the same location/model as ground shadows.
Daylight/civil twilight/night follow geometric elevation (0/-6 degree thresholds).
Polar missing events are explicit. Native map sky/light and scene colours change
with the sun; labels/boundaries remain visible. Geographic sun disc/direction and
optional visible-sky path respond to camera bearing/pitch; no invented streetlights.
Old shadows are hidden while updating; superseded requests are cancelled. Night
reports No direct sunlight. Sun/path are not roof-aware occlusion calculations.
Selected site transfers unchanged; time becomes reviewable new-brief context,
not a silent overwrite of saved project analysis. Resources: R19, R21.

E07 - Manual cloud, rain and storm simulation [BUILT; DEVICE ACCEPTANCE OPEN]
Clear, Partly Cloudy, Overcast, Light Rain, Heavy Rain and Storm presets;
cloud/rain/wind numeric and slider controls, direction, effects on/off,
Low/Medium/High quality and animation pause. Procedural GPU clouds/rain follow
camera/wind changes; reduced motion and hidden tabs suppress continuous motion.
Clearly labelled Simulated weather. Visual intensity is not mm/hour or a forecast.
Weather never changes numerical shade, quantities, estimates or saved decisions.
No lightning/audio, paid resources or external assets. Resources: R19-R20.
Physical weak-device and prolonged context-loss/soak acceptance remains open.

E08 - Live weather-data integration [OPTIONAL; NOT BUILT]
Not required by the E06/E07 task. No API subscription, weather service, or inactive
Live Weather button added. Future provider terms/privacy/data-age handling would
need a separate decision. Manual scenarios are not observations or forecasts.
